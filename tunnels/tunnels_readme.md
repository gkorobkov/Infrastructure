# tunnels

Три способа открыть публичный HTTPS-доступ к локальному HTTP-серверу: Cloudflare Quick Tunnel, ngrok и localtunnel. Подходят для учебных демонстраций n8n, FastAPI и Node.js. Сервер приложения пользователь запускает отдельно.

## Архитектура

```text
Web UI https://service-name.ru
  → HTTPS → публичный адрес провайдера + /webhook/my-agent
  → клиент туннеля на компьютере
  → HTTP → http://127.0.0.1:5678/webhook/my-agent
```

Web UI может находиться на любом внешнем HTTPS-адресе. Запросы к публичному адресу туннеля также могут отправлять другие внешние клиенты: приложения, серверы и инструменты API. Архитектура не привязана к конкретному сайту.

TLS завершается у провайдера, поэтому сертификат на localhost не требуется. Скрипт публикует весь локальный HTTP-сервер, а не только указанный webhook: `WebhookPath` служит для формирования ссылки. Доступ к UI и другим маршрутам регулируется самим приложением.

Три файла `tunnels_start_*.ps1` вызывают общие функции из `tunnels_common.ps1`. Небольшой C#-компонент `tunnels_process.cs` читает stdout/stderr асинхронно и связывает клиент и его потомков с Windows Job Object. Скрипт остаётся работать до Ctrl+C или завершения клиента; при выходе закрывает принадлежащий ему Job. Другие процессы не останавливаются. URL не записывается в проект.

## Выбор провайдера

| Критерий | Cloudflare | ngrok | localtunnel |
|---|---|---|---|
| Аккаунт | Не нужен для Quick Tunnel | Нужен authtoken | Обычно не нужен |
| HTTPS | Да | Да | Да |
| Локальный сертификат | Не нужен | Не нужен | Не нужен |
| Адрес | Временный, меняется при запуске | Зависит от аккаунта и настроек | Временный |
| Зависимость | cloudflared | ngrok | Node.js LTS, npm/npx |
| Порядок выбора | 1 | 2 | 3 |
| Особенности | Без SLA и SSE, до 200 запросов одновременно | Ограничения аккаунта, возможна страница предупреждения | Возможна страница reminder/password |

Для SSE выберите другой вариант вместо Quick Tunnel. Условия тарифов и доступность провайдеров могут меняться.

## Требования и быстрый старт

Windows 10/11, Windows PowerShell 5.1 или PowerShell 7, работающий HTTP-сервер и доступ к провайдеру через интернет. Docker и WSL самим туннелям не нужны. n8n из соседнего каталога может использовать Docker независимо от них. Обычно права администратора не требуются.

Запустите приложение, затем из корня репозитория выберите **один** вариант:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tunnels\tunnels_start_cloudflare.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tunnels\tunnels_start_ngrok.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tunnels\tunnels_start_localtunnel.ps1
```

Сначала проверьте источник скриптов. `-ExecutionPolicy Bypass` относится только к новому процессу PowerShell и не меняет глобальную политику. Для PowerShell 7 замените `powershell.exe` на `pwsh`.

При отсутствии клиента появится предложение установки через winget. `-InstallIfMissing` разрешает установку без дополнительного вопроса, а для localtunnel также разрешает загрузку пакета через npx. Скрипт использует только источник winget и проверку хеша пакета, пытаясь установить его с `--scope user`. Если пакет не поддерживает такой режим или winget отсутствует, сообщение укажет официальный источник portable/zip для ручной установки без UAC. Выберите архитектуру Windows (x64/ARM64/x86) и добавьте каталог в пользовательский PATH. После установки повторите запуск; при необходимости откройте новый терминал. Скрипты не устанавливают зависимости при автоматических тестах.

## Параметры

```powershell
# FastAPI на порту 8000; health endpoint без побочных эффектов
.\tunnels\tunnels_start_cloudflare.ps1 -Port 8000 -WebhookPath '/api/hook?mode=demo' -HealthPath /health -InstallIfMissing

# Тестовый webhook n8n
.\tunnels\tunnels_start_ngrok.ps1 -WebhookPath /webhook-test/my-agent -NgrokApiPort 45001

# Увеличенное время ожидания и диагностика без сырых логов клиента
.\tunnels\tunnels_start_localtunnel.ps1 -StartupTimeoutSeconds 180 -VerboseOutput
```

| Параметр | Значение по умолчанию / назначение |
|---|---|
| `Port` | `5678`, диапазон 1–65535 |
| `LocalHost` | `127.0.0.1`; также разрешены `localhost` и `::1` |
| `WebhookPath` | `/webhook/my-agent`, query string сохраняется |
| `HealthPath` | `/`; GET только к безопасному маршруту проверки |
| `InstallIfMissing` | Разрешить установку зависимостей и загрузку localtunnel |
| `SkipPublicCheck` | Пропустить публичный GET, сохранив локальные проверки |
| `StartupTimeoutSeconds` | `90`, максимум `600` |
| `VerboseOutput` | Показывать безопасные коды ошибок ngrok; сырые логи не печатаются |
| `NgrokApiPort` | Только ngrok: `0` выбирает свободный loopback-порт |
| `NgrokConfig` | Только ngrok: существующий конфиг v2/v3; иначе поиск стандартного профиля |

Пути начинаются с одного `/`, не содержат пробелов, `#`, обратных слешей и управляющих символов. Query string заключайте в одинарные кавычки, чтобы оболочка не интерпретировала `&` и `$`. Скрипты не принимают внешние адреса в `LocalHost`.

## Runbook: получить URL и подключить Web UI

1. Убедитесь, что приложение доступно локально на выбранном порту.
2. Запустите один из трёх скриптов. Для ngrok при необходимости введите authtoken скрыто.
3. Дождитесь блока `URL RECEIVED` с реальными `Public URL` и `WEBHOOK URL`.
4. Скопируйте полный `WEBHOOK URL` в настройки вашего Web UI или другого внешнего клиента — например, в [AI Agents Lab](https://ai-agents-lab.gkorobkov.ru/index.html).
5. Отправьте тестовый запрос из UI и проверьте ответ и журнал приложения.
6. Для остановки нажмите Ctrl+C в терминале скрипта. Для переключения остановите его и запустите скрипт другого провайдера. Замените адрес в UI после смены URL.

Получение URL, публичный HTTP-ответ, доставка в приложение и успешный POST — разные проверки. Скрипт проверяет локальный TCP и HTTP GET, получает URL и выполняет публичный GET, если он не отключён. Ответы 401/403/404 подтверждают HTTP-ответ, но не правильность webhook. Публичный ответ может быть страницей провайдера; доставка запроса к приложению автоматически не подтверждается. Неудачный публичный GET не останавливает туннель. POST автоматически не отправляется.

При выборе `HealthPath` убедитесь, что GET к нему ничего не меняет. Не используйте webhook с побочными эффектами как health endpoint. Таймаут TCP — 2 секунды, HTTP — 5 секунд; ожидание первоначального URL ограничено отдельно. После получения URL скрипт работает до остановки пользователем либо выхода клиента.

## n8n и браузер

`/webhook-test/<path>` работает во время ожидания тестового события в редакторе n8n. `/webhook/<path>` требует опубликованного/активного workflow согласно установленной версии. Выберите правильный путь и метод в Webhook node. Для ручного обращения по адресу туннеля настройка `WEBHOOK_URL` не всегда обязательна; она может понадобиться для формирования правильных ссылок самим n8n. Скрипты не меняют её и не перезапускают n8n.

HTTPS-туннель не добавляет CORS-заголовки. Для браузерного запроса разрешите фактический origin вашего Web UI в приложении и проверьте OPTIONS, разрешённые методы и заголовки. Если браузер сообщает Local Network Access, убедитесь, что UI использует публичный HTTPS URL, а не localhost. Не отключайте защиту браузера.

## Безопасность

Любой обладатель URL может попытаться обратиться к серверу. Применяйте авторизацию, проверку запросов и ограничение доступа в приложении. Используйте временные учебные данные; останавливайте туннель после работы. Токены, базы и логи не публикуйте. Токен ngrok не передаётся параметром скрипта и не записывается в проект: скрытый ввод используется только в окружении дочернего процесса. Это не защищает от привилегированных процессов на самом компьютере. Не вставляйте секреты в `WebhookPath`.

## Диагностика и проверки

См. [Cloudflare](docs/tunnels_cloudflare.md), [ngrok](docs/tunnels_ngrok.md), [localtunnel](docs/tunnels_localtunnel.md) и [разбор ошибок](docs/tunnels_troubleshooting.md).

Автоматические проверки без установки программ и реальных аккаунтов:

```powershell
Invoke-Pester .\tunnels\tests\tunnels_scripts.Tests.ps1
```

Они проверяют входные данные, URL/query string, отказы HTTP/TCP, согласие на установку, API ngrok с mock-ответами, таймаут и завершение собственного процесса с большим stdout/stderr. Реальный сетевой smoke test выполняется отдельно:

1. Запустите тестовый сервер, например `python -m http.server 8000 --bind 127.0.0.1` в пустой папке без личных файлов.
2. Запустите выбранный туннель с `-Port 8000 -WebhookPath /`.
3. Выполните `Invoke-WebRequest -UseBasicParsing 'https://<адрес-из-вывода>/'` и сравните ответ с локальным сервером; проверьте журнал сервера.
4. Нажмите Ctrl+C; убедитесь, что выведенный PID клиента исчез, а тестовый сервер продолжает работать.
5. Повторите для других провайдеров. Для проверки завершения потомков localtunnel проверьте также дочерний процесс Node.js.

Unit-тесты не подтверждают доступность публичных сервисов, авторизацию аккаунта, поведение Ctrl+C в каждом терминале, UAC/установку и PowerShell 7. Фактические результаты текущего прогона приведены в отчёте к изменению.

Официальные источники: [Cloudflare Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/), [ngrok CLI](https://ngrok.com/docs/gateway/agent/cli), [конфигурация ngrok](https://ngrok.com/docs/gateway/agent/config/v3), [localtunnel](https://github.com/localtunnel/localtunnel), [Webhook n8n](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.webhook/).
