# Диагностика туннелей

Все команды ниже запускаются из корня репозитория. Сначала проверьте локальное приложение, затем клиент и публичный адрес. GET выполняйте только к безопасному маршруту. Не отправляйте повторно рабочий POST без понимания его побочных эффектов.

| Симптом | Возможная причина | Проверка и исправление | Когда сменить провайдера |
|---|---|---|---|
| Local server unavailable / connection refused / закрытый порт | Приложение не запущено, неверный порт или IPv4/IPv6 | `Test-NetConnection 127.0.0.1 -Port 5678`; запустите приложение, исправьте `Port`/`LocalHost` | Смена не поможет до запуска сервера |
| TCP доступен, HTTP не отвечает | Выбран не HTTP-сервис или приложение зависло | `Invoke-WebRequest -UseBasicParsing http://127.0.0.1:5678/`; проверьте протокол и журнал приложения | После исправления локального HTTP |
| Command not found | Нет клиента или каталога в PATH | `Get-Command cloudflared.exe`, `Get-Command ngrok.exe`, `Get-Command node.exe`; установите официальный клиент, откройте новый терминал | Если установка блокируется политиками |
| Package installation failed | winget недоступен, пакет не поддерживает user scope, нет сети | Прочитайте код winget; используйте официальный portable/zip и пользовательский PATH | Если запрещена установка выбранного клиента |
| Authentication failed | Нет аккаунта, неправильный/revoked authtoken или передан API key | Проверьте dashboard ngrok; повторите скрытый ввод с действительным authtoken | Cloudflare не требует аккаунта |
| ngrok account limit exceeded | Лимит сессий/трафика/аккаунта | Посмотрите dashboard, завершите ненужные собственные сессии; не обходите лимит | Cloudflare/localtunnel при исчерпанном лимите |
| Служебный API-порт занят | Другой процесс использует порт | Повторите с `-NgrokApiPort 45001`; не завершайте неизвестный процесс | Если API недоступен из-за политики компьютера |
| Tunnel URL not found / timeout | Клиент не подключился, формат/домен не поддерживается или сервис недоступен | Повторите с `-StartupTimeoutSeconds 180 -VerboseOutput`; проверьте версию клиента и сеть | После повторяющейся ошибки конкретного провайдера |
| HTTP 502/503/504 | Приложение упало, неверный upstream или сбой провайдера | Повторите локальный GET, сравните с публичным, проверьте журнал сервера | Если локальный сервер отвечает, а провайдер стабильно нет |
| HTTP 401/403/404 | Авторизация, неправильный маршрут, webhook не зарегистрирован или страница провайдера | Проверьте тело ответа вручную, путь, метод и авторизацию. HTTP-ответ сам по себе не доказывает успех webhook | Если отвечает блокирующая страница провайдера |
| Browser CORS error | Приложение не разрешило origin/OPTIONS/заголовки | DevTools → Network: проверьте OPTIONS и CORS для origin UI; настройте приложение | Смена туннеля обычно не исправляет CORS |
| Local Network Access | UI обращается к localhost/частному IP | Укажите публичный HTTPS URL в UI; проверьте адрес в Network | Сначала исправьте адрес; не отключайте защиту браузера |
| n8n webhook not registered | Не включено тестовое ожидание или workflow не опубликован | Для `/webhook-test/` включите ожидание, для `/webhook/` опубликуйте/активируйте workflow и проверьте метод | Смена не поможет при неверном режиме n8n |
| Cloudflare Quick Tunnel unavailable | Сбой сервиса, ограничения сети, конфликт config.yaml/yml | Проверьте `.cloudflared`; сохраните профиль самостоятельно или используйте отдельный Windows-профиль | ngrok при недоступности Quick Tunnel или необходимости SSE |
| localtunnel confirmation/password page | Провайдер требует ручного подтверждения | Откройте URL и проверьте ответ; не считайте HTML успешным webhook и не обходите защиту | Предпочтительно Cloudflare/ngrok для автоматических запросов |
| Windows Firewall / Antivirus | Заблокирован клиент/исходящие соединения | Проверьте уведомления и журнал защиты с администратором; не отключайте защиту целиком | Если политика разрешает другой клиент |
| Proxy / VPN / DNS / TLS error | Ограничения сети, неверные часы, TLS interception | Проверьте системное время, DNS провайдера и разрешённые сетевые настройки; отсутствие ответа одного сайта не означает отсутствие интернета | Если сбой относится к одному провайдеру |
| URL changed after restart | Временный адрес | Скопируйте новый `WEBHOOK URL` в UI | Для постоянного адреса нужна отдельная конфигурация/план |
| Tunnel closed unexpectedly | Клиент завершился, потеря сети, лимит | Скрипт сообщает код выхода, закрывает свой Job; проверьте сеть/dashboard и перезапустите | При повторяющихся сбоях одного сервиса |

Если ngrok нужно диагностировать отдельно, `ngrok config check` проверяет пользовательский профиль. Не публикуйте полный конфиг, токены, журналы запросов и снимки с секретами. `-VerboseOutput` в скриптах показывает безопасные коды ошибок без сырых логов.
